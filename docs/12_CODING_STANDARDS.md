
# Coding Standards

## General Principles
- Write readable, maintainable code.
- Prefer clarity over cleverness.
- Follow SOLID, DRY, and KISS.
- Keep functions focused on a single responsibility.

## Naming
- PascalCase: Components & Classes
- camelCase: Variables & Functions
- UPPER_SNAKE_CASE: Constants
- snake_case: Python modules

## Backend
- Thin controllers
- Business logic in services
- Data access in repositories
- Validate all inputs
- Structured exceptions only

## Frontend
- Feature-based folders
- Reusable components
- Shared hooks
- No duplicated UI logic

## Documentation
- Public functions should include docstrings/comments where appropriate.
- Keep README and API docs updated with every feature.
